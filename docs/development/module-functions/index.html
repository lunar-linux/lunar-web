Module Function Reference

The Lunar functions and variables available in module files, grouped by the file they are used in

Last updated: November 22, 2026

Lunar runs module files in bash with its own function library loaded, so DEPENDS, BUILD, POST_INSTALL and the others can call these functions directly. This page lists the ones modules use, grouped by where they are used. Module Basics explains the files themselves.

All of them are ordinary shell functions that return true or false, so chain them with && like any other command.

Dependencies

Used in DEPENDS and CONFLICTS, and nowhere else. The DEPENDS File describes them in full.

FunctionDoes
depends moduleAlways installs module before this one
optional_depends module on off "for ..." [y|n]Asks the user, and adds on or off to $OPTS
optional_depends_requires leader followers...Makes the followers take the leader's answer
optional_depends_one_of "heading" module on off ...Lets the user choose one module out of several
conflicts moduleRemoves module when this one is installed (CONFLICTS)

Preparing the Source

Used in PRE_BUILD.

FunctionDoes
default_pre_buildWhat runs without a PRE_BUILD: creates $SOURCE_DIRECTORY, unpacks $SOURCE and changes into it
unpack fileUnpacks $SOURCE_CACHE/file into the current directory: unpack $SOURCE2
mk_source_dir [dir]Creates an empty dir (default $SOURCE_DIRECTORY), removing an old one first
sedit 'expression' file...Runs sed -i on the files
patch_it file levelApplies a patch, compressed or not, with patch -p<level>; a bare file name is looked up in $SOURCE_CACHE

sedit doesn't report when the expression matches nothing, so check that your edits still apply after a version bump. For patches that ship with the module, the patch.d directory is simpler than patch_it: see Module Directories.

Building

Used in BUILD. The build commands run in $SOURCE_DIRECTORY.

FunctionDoes
default_buildWhat runs without a BUILD: picks one of the builds below by TYPE
default_gnu_builddefault_config, then default_make (the build when TYPE isn't set)
default_config./configure with Lunar's prefix and directories, plus $OPTS
default_makemake, then default_install
default_installprepare_install, then make install
default_meson_builddefault_meson_config, ninja, prepare_install, ninja install
default_meson_configmeson setup into $MODULE-$VERSION/, with $OPTS
default_cmake_builddefault_cmake_config, cmake --build, prepare_install, cmake --install
default_cmake_configcmake -B $MODULE-$VERSION (Ninja if installed), with $OPTS
default_python3_buildpython3 setup.py build and install, for projects that still ship a setup.py
default_perl_buildMakefile.PL or Build.PL
default_game_buildautotools, installing into /usr/games and /usr/share/games
prepare_installRemoves the installed version and starts recording installed files
bad_flags flag...Removes flags from CFLAGS, CXXFLAGS, CPPFLAGS and LDFLAGS

The usual BUILD adds options and calls one of the defaults:

# /var/lib/lunar/moonbase/net/iputils/BUILD
OPTS+=" -DBUILD_MANS=false \
        -DBUILD_HTML_MANS=false"

default_meson_build

The *_config functions only configure. Call one when you need your own build or install commands after it: the build directory is $MODULE-$VERSION, inside the source.

Every BUILD that installs files itself must call prepare_install first, right before installing; see prepare_install.

bad_flags takes flags to remove (bad_flags -ffast-math), or compiler, linker or ALL to drop the compiler flags, the linker flags or both. Use it when software breaks with the user's optimizations.

Installing Extra Files

Used in BUILD, after prepare_install, or in POST_BUILD.

FunctionDoes
gather_docs file...Copies files or directories from the source into the module's directory in /usr/share/doc
ld_add dirAdds a library directory to the module's file in /etc/ld.so.conf.d and runs ldconfig
ld_remove dirRemoves it again
devoke_installwatchStops recording installed files
invoke_installwatchStarts recording again
add_priv_group groupCreates a system group, if it doesn't exist
add_priv_user user:groupCreates a system user and its group, if they don't exist

Files written while recording is stopped don't belong to the module, so lrm leaves them behind. Use that only for files that must survive a removal.

For new modules, create users and groups with a sysusers.d file instead of add_priv_user and add_priv_group: see Module Directories.

Asking and Remembering

Used in CONFIGURE, and read back in BUILD or POST_INSTALL. Answers are saved per module, so the user is asked again only when they reconfigure it (lin -r). See The CONFIGURE File.

FunctionDoes
mquery VAR "question" y|n [yes_opts] [no_opts]Asks once, saves y or n as VAR, and adds the matching options to $OPTS
query "question" y|nAsks a yes/no question every time and returns true for yes
get_module_config VARPrints the saved value of VAR
set_module_config VAR valueSaves a value
unset_module_config VARForgets it, so mquery asks again

When nobody answers within PROMPT_DELAY seconds, query and mquery take the default.

Checking the System

Usable in any bash module file except DEPENDS.

FunctionDoes
module_installed moduleTrue if module is installed (or held)
in_depends $MODULE dependencyTrue if the user chose dependency for this module (or it is a required one)
installed_version modulePrints the installed version
module_version modulePrints the version in the moonbase
kernel_option_present OPTION [value]True if the running kernel's configuration has OPTION set to y or m (or to value)

Use in_depends rather than module_installed to test an optional dependency: a module can be installed without the user having chosen it for this one. wget's BUILD picks its TLS library that way:

# /var/lib/lunar/moonbase/ftp/wget/BUILD (excerpt)
if in_depends $MODULE openssl || in_depends $MODULE libressl; then

kernel_option_present returns 255 when it can't find a kernel configuration, so test for that before treating a false result as "not set".

Messages

FunctionDoes
message text...Prints text, unless Lunar runs silently
verbose_msg text...Prints text only in verbose mode (lin -v)

message understands the escape sequences of echo -e, and the color variables Lunar uses, such as ${MESSAGE_COLOR} and ${DEFAULT_COLOR}.

Variables

Set by Lunar while it runs a module's files:

VariableHolds
MODULE, VERSIONThe module's name and version, from DETAILS
SOURCE, SOURCE2, ...The source file names, from DETAILS
SOURCE_DIRECTORYWhere the source is unpacked; by default $MODULE-$VERSION in $BUILD_DIRECTORY
BUILD_DIRECTORYThe parent of all source directories, /usr/src
SOURCE_CACHEWhere downloads are kept, /var/spool/lunar
SCRIPT_DIRECTORYThe module's own directory in the moonbase, for files shipped with the module
MODULE_PREFIXThe install prefix, /usr unless DETAILS sets it
OPTSBuild options collected from DEPENDS, CONFIGURE and lin --opts
PLATFORMThe machine type, as in DETAILS.x86_64

During a CATALYST trigger, CATALYST_MODULE and CATALYST_MODULE_VERSION hold the name and version of the module that set it off.

Add to OPTS with OPTS+=" --option", so the options from DEPENDS and CONFIGURE are kept.

Since the module files are bash, a BUILD can also define its own shell functions when it repeats itself.

Reading the Source

The functions live in /var/lib/lunar/functions and /var/lib/lunar/plugins on an installed system, and in libs/ and plugins/ of the lunar repository. Most of them start with a comment that gives their usage. Other functions you find there are Lunar's own internals and can change, so modules shouldn't rely on them.
